# 复现步骤与修复方向（含答案）

每关建议从页面「重置靶场」开始，使用 alice / Alice123!。不同漏洞会改变共享钱包、角色、密码和折扣；全局重置可避免互相影响。

请求体为 JSON，使用页面「接口实验台」发送，默认自动携带登录 Cookie。返回的 FLAG 大多自动记录；crypto 需要手动提交。XSS 需在浏览器实际执行留言页；本靶场没有防作弊机制。

## 01. 隔壁的订单 · idor

**入口：** `GET /api/orders/1002`

**目标：** 用 Alice 的身份读取 Bob 的订单。

**复现：** 登录 alice 后请求 GET /api/orders/1002。接口只检查登录，没有检查订单归属。

**修复：** 在数据库查询中同时绑定订单 ID 与当前用户 ID；对每次对象访问进行授权。

## 02. 自己给自己升职 · mass

**入口：** `POST /api/profile`

**目标：** 普通账号通过修改个人资料成为管理员。

**复现：** 以普通用户发送 {"nickname":"Alice","role":"admin"} 到 /api/profile。

**修复：** 更新字段使用白名单；角色等敏感属性使用独立的管理接口。

## 03. 预览器背后的内网 · ssrf

**入口：** `GET /api/preview?url=...`

**目标：** 让服务器的链接预览器访问靶场内部的模拟元数据。

**复现：** 登录后让 /api/preview?url=http%3A%2F%2F127.0.0.1%3A9091%2Fmetadata 访问内部服务。真实发出 HTTP 请求，但出口被教学沙箱限定为这个服务。

**修复：** 业务 URL 校验必须排除环回、私网、保留地址及重定向；结合网络出口限制。

## 04. 忘关的调试面板 · debug

**入口：** `GET /debug`

**目标：** 发现公开的调试配置和演示数据库备份。

**复现：** 打开 /debug，获得配置、虚构密钥以及演示账号备份。

**修复：** 关闭调试接口，阻止备份文件和配置进入 Web 发布目录。

## 05. 来路不明的促销插件 · supply

**入口：** `POST /api/plugins/install`

**目标：** 让商城启用未验证来源的促销规则。

**复现：** 普通账号提交未签名的插件清单即可影响实际结算折扣。此题只加载声明式规则，不下载或执行外部代码，也不演示旧组件 CVE。

**修复：** 限定可信来源，验证签名和摘要，审查构建与发布权限；业务规则另行限制。

## 06. 编码不是加密 · crypto

**入口：** `GET /api/exports/customers`

**目标：** 解开客户导出文件中的敏感数据，提交其中的 FLAG。

**复现：** 请求导出接口，对 ciphertext 做 Base64 解码，将 recovery_note 中的 FLAG 提交至 /api/submit。导出中还存在弱 MD5 摘要。

**修复：** 敏感数据使用标准认证加密并管理密钥；密码使用 Argon2id 等专用哈希。

## 07. 万能登录口令 · sqli

**入口：** `POST /api/login`

**目标：** 利用 SQL 注入绕过密码检查。

**复现：** 发送 {"username":"alice' -- ","password":"wrong"} 到 /api/login。

**修复：** 使用参数化查询；不要通过过滤单引号修补 SQL 拼接。

## 08. 会执行的商品留言 · xss

**入口：** `POST /api/reviews · GET /reviews`

**目标：** 通过存储型 XSS 让留言页执行一次靶场证明请求。

**复现：** 把提示中的 img 留言存储到 /api/reviews，浏览器打开 /reviews 时 onerror 会执行同源证明请求。API 测试只证明未转义，浏览器执行另行验证。

**修复：** 按输出上下文编码；需要富文本时使用成熟净化器，并配置 CSP。

## 09. 一分钱买键盘 · price

**入口：** `POST /api/orders`

**目标：** 篡改客户端单价，以低于目录价格下单。

**复现：** 使用 1 分单价购买原价 29900 分的商品。订单总额由请求参数计算。

**修复：** 单价、税费与折扣在服务端从可信数据计算。

## 10. 负数也能下单 · negative

**入口：** `POST /api/orders`

**目标：** 创建负数量订单，观察钱包余额反向增加。

**复现：** 下单 quantity=-1；服务端从钱包扣负金额，相当于充值。上限仍受教学资源边界约束。

**修复：** 数量必须为受限的正整数；所有金额和库存操作检查业务不变量。

## 11. 无限新客优惠 · coupon

**入口：** `POST /api/coupons/redeem`

**目标：** 同一个账号两次兑换一次性优惠券。

**复现：** 两次发送 {"code":"WELCOME50"}；余额各增加 5000 分。

**修复：** 使用数据库唯一约束和事务保证一次兑换，记录用户与券的关系。

## 12. 重置别人的密码 · reset

**入口：** `POST /api/reset/confirm`

**目标：** 不提供有效重置令牌，修改 Bob 的密码。

**复现：** 登录 alice，发送 {"username":"bob","new_password":"Changed123!"} 到 /api/reset/confirm，然后用 Bob 新密码登录。

**修复：** 重置令牌须随机、单次、短时有效并绑定目标用户；成功后使旧会话失效。

## 13. 会员 Cookie 的秘密 · cookie

**入口：** `GET /api/vip`

**目标：** 篡改未签名的会员 Cookie，获得管理级会员权益。

**复现：** 登录后把 profile Cookie 改成 eyJyb2xlIjoiYWRtaW4ifQ==，请求 /api/vip。数据库角色仍可保持 user。

**修复：** 权限由服务端可信会话决定；如必须传输状态，验证签名和完整性。

## 14. 没人听见的失败登录 · audit

**入口：** `GET /api/audit/status`

**目标：** 制造五次失败登录，确认没有安全审计或告警。

**复现：** 五次错误登录后，/api/audit/status 显示 failed_logins>=5、security_events=0、alerts=0。一般访问日志不等于安全审计。

**修复：** 记录结构化安全事件，避免敏感数据入日志，并为异常失败频率配置告警。

## 15. 风控异常，直接放行 · failopen

**入口：** `POST /api/risk/check`

**目标：** 触发风控评分解析异常，让异常处理默认批准。

**复现：** 先提交 {"risk_score":99} 看到拒绝，再提交 {"risk_score":"timeout"}；异常分支返回批准。

**修复：** 安全关键控制异常时拒绝或挂起；不要用宽泛捕获默许成功。

## 16. 自己签收支付成功 · payment

**入口：** `POST /api/payments/callback`

**目标：** 伪造小额支付回调，让高额订单变成已支付。

**复现：** 对自己的正常价格订单发送金额 1 分的 paid 回调；接口没有校验来源、签名或应付金额。

**修复：** 验证支付网关签名与订单金额、币种、商户号和状态，并保证幂等。

## 17. 没付款先发货 · workflow

**入口：** `POST /api/orders/{id}/ship`

**目标：** 对待付款订单直接发起发货。

**复现：** 创建正常待付款订单后，POST /api/orders/订单号/ship。该接口没有检查支付状态。

**修复：** 服务端强制执行合法状态迁移；支付状态只能由可信支付流程更新。

## 18. 一单退两次 · refund

**入口：** `POST /api/orders/{id}/refund`

**目标：** 让同一个已支付订单重复向钱包退款。

**复现：** 对正金额订单先 POST /api/orders/订单号/pay，再 POST refund 两次；第二次仍增加余额。

**修复：** 退款操作使用幂等键、状态校验和数据库事务；总退款额不能超过实付金额。

## 19. 点击链接就换邮箱 · csrf

**入口：** `GET /api/profile/email?email=...`

**目标：** 通过无令牌的 GET 请求修改登录用户邮箱。

**复现：** 保持登录，从外部 HTML 链接顶层导航至上述地址；SameSite=Lax 仍允许顶层 GET 携带 Cookie。

**修复：** GET 不得修改状态；使用 POST、CSRF 令牌，并检查 Origin。

## 20. 旧模板组件的路径穿越 · component

**入口：** `GET /api/legacy-template?name=...`

**目标：** 绕过内置旧版教学组件的路径限制，读取虚构备份。

**复现：** 请求 name=../customers-demo.csv，读取模板目录以外的虚构客户备份。这是本仓库自制的有缺陷组件，不是真实第三方 CVE；文件访问仍被限定在 fixtures 目录内。

**修复：** 组件版本和来源需要维护；规范化路径后验证目录边界并禁用任意模板路径。

## 推荐的修复练习

保留漏洞版本作为基线，在独立分支修复一个问题，并将相关测试从「断言漏洞可复现」改为「断言攻击被拒绝、正常流程仍成功」。例如退款测试应断言第二次退款返回 409，余额保持初始金额；单纯删除 FLAG 不算修复。

## 代理抓包

浏览器代理指向本机 Burp Suite，目标为自己的 http://127.0.0.1:8080。使用独立浏览器配置进行练习；若环回请求绕过代理，可使用专门的测试浏览器或直接在 Repeater 构造请求。每次切换账号重新获取 sid Cookie。
